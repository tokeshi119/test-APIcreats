# ステップ1: 画面要件の分析

## 画面名
友だち一覧画面

## 表示データ項目

### 友だち情報テーブルの各列

| 画面表示項目 | データ型 | 必須/任意 | 備考 |
|------------|---------|----------|------|
| 管理ID | string | 必須 | 友だちを一意に識別するID（`line_friends.id` または `messaging_api_user_id`） |
| 管理コード | string | 必須 | CMS向けMessaging API ユーザーID（`messaging_api_user_id_cms`）**【要確認】** 画面の「管理コード」列が実際に `messaging_api_user_id_cms` を表示しているか確認が必要 |
| 広告コード | string | 任意 | 広告コード文字列（`advertisement_codes.advertisement_code`、JOIN必要） |
| LINE ID | string | 必須 | Messaging API ユーザーID（`messaging_api_user_id`） |
| 友だち登録日時 | string (ISO 8601) | 必須 | 登録日時（`created_at`） |
| 友だち状態 | string | 必須 | 「ブロック」または「正常」（`is_blocked`から変換、true=ブロック、false=正常） |
| LINE連携 | object | 必須 | LINE公式アカウント情報（`line_official_account_id`と関連情報） |

### その他の表示情報

| 項目 | データ型 | 必須/任意 | 備考 |
|-----|---------|----------|------|
| 検索結果件数 | integer | 必須 | 現在の検索条件に該当する総件数 |
| ページ番号 | integer | 必須 | 現在のページ番号 |
| 総ページ数 | integer | 必須 | ページネーション用の総ページ数 |

## ユーザー操作

### 検索機能
- **検索対象フィールド**: 未明確（画面からは検索UIが見えないが、検索結果9件と表示されているため検索機能は存在）
- **推測される検索対象**:
  - 管理コード（部分一致）
  - 広告コード（部分一致）
  - LINE ID（部分一致）
  - 管理ID（完全一致または部分一致）

### フィルタ/絞り込み
- **友だち状態**: 「ブロック」「正常」でフィルタ可能と推測
- **広告コード**: 特定の広告コードで絞り込み可能と推測
- **LINE連携**: 特定のLINE公式アカウントで絞り込み可能と推測

### ソート機能
- 画面からは明確ではないが、一般的に以下の項目でソート可能と推測:
  - 登録日時（新着順/古い順）
  - 管理ID
  - 管理コード

### ページネーション
- **あり**: ページ番号によるページネーション（`< 1 2 3 4 >`）
- **デフォルト件数**: 画面からは不明（一般的に10件、20件、50件など）

### データ操作
- **削除**: 各友だちに対して「削除」ボタンが存在
  - 操作対象: 特定の友だち（管理IDで識別）

### 一括操作
- 画面からは複数選択のUIは見えないが、将来的に一括削除などの機能追加の可能性あり

## 関連画面

### ナビゲーションメニューから推測される関連画面
- **集計**: 友だち登録数の集計情報を表示（別API）
- **LINE設定**: LINE公式アカウントの設定（別API）
- **広告設定**: 広告コードの設定（別API）

### 画面間の遷移で引き継ぐデータ
- 友だちの管理ID（詳細画面への遷移時に使用する可能性）
- 検索条件やフィルタ条件（一覧画面に戻る際に状態を保持）

## DDLとの対応関係

### line_friends テーブル
- 主テーブルとして使用
- `site_id` によるマルチテナント対応（認証情報から取得）

### advertisement_codes テーブル
- `line_friends.advertisement_code_id` でJOINして広告コード文字列を取得

### line_official_accounts テーブル
- `line_friends.line_official_account_id` でJOINしてLINE連携情報を取得
